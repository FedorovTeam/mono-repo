Сгенерируй Mermaid `sequenceDiagram`, показывающий поведение сервиса на уровне Dynamic View.

🎯 Цель:
Отразить взаимодействие между участниками во времени при выполнении ключевого бизнес-сценария.

📌 Требования:
- Покажи последовательность действий между пользователем, внешними API, gateway, микросервисами, базами данных, брокерами сообщений.
- Отрази вызовы HTTP/gRPC, события в брокерах (например, NATS, Kafka), взаимодействие с БД (чтение/запись).
- Учитывай асинхронные действия, ретраи, таймауты, обработку ошибок и fallback-логику, если она есть.
- Строго отталкиваться от исходного кода сервиса, а не документации
- Используй реальные или типовые названия:
    - HTTP endpoints (например, `POST /api/v1/sales`)
    - gRPC методов (например, `SaveSale`)
    - топиков (например, `sale.created.v1`)
    - запросов в БД (например, `INSERT INTO sales`)

🛠 Формат:
- Используй `sequenceDiagram` в синтаксисе Mermaid
- Обязательно указывай участников: `participant`
- Используй стрелки: `->>`, `-->>`, `x-->>`, `Note over`, `opt`, `alt`, `loop` при необходимости
- Названия шагов и сообщений должны быть понятными
- Вставляй комментарии к ключевым действиям (//)

📂 Вывод:
Диаграмму нужно сохранить в папке сервиса с названием sequence в формате MD внутри которого хранится Mermaid
