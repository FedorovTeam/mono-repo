Обнови Markdown-документацию `usecases.md`, описывающую бизнес-сценарии (use cases), реализованные в сервисе.

🎯 Цель:
Документировать пользовательские и интеграционные сценарии, которые реализует сервис, на языке целей, шагов и задействованных компонентов.

📌 Требования:
- Отталкивайся строго от **исходного кода** и структуры сервисных методов, а не от документации
- Для каждого сценария укажи:
    - 🎯 Название сценария (коротко: «Сохранение новой интеграции», «Получение маппинга по clientID»)
    - 📋 Описание цели (что делает и зачем)
    - 🧩 Участники (например: `CRM`, `1С`, `gateway`, `админ`)
    - 📥 Входные данные (например, `POST /api/v1/mapping`, `gRPC SaveMapping`)
    - 📤 Выходной результат (успешный ответ или отправка события)
    - 🔄 Поток выполнения — пошагово, что вызывает что (можно в виде маркированного списка)
    - 💥 Ошибки и edge cases (если есть важные)

- Используй реальные endpoint'ы, методы, protobuf-функции и топики сообщений
- Упоминай названия структур из кода, если они явно фигурируют (`ClientIntegration`, `MappingRequest`)
- Структурируй Markdown с заголовками (`##`, `###`, `-`, `1.`)

🛠 Формат:
- Markdown (`usecases.md`)
- Один сценарий = одна секция (`## Название`)
- Внутри — подразделы: `Описание`, `Участники`, `Вход`, `Выход`, `Шаги`, `Ошибки`

📂 Вывод:
Файл `usecases.md` нужно сохранить в корневой директории сервиса

🧩 Контекст:
Сервис: <название сервиса>
