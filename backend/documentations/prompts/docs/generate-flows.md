Сгенерируй Markdown-документацию `flows.md`, описывающую пользовательские и системные потоки (flows), проходящие через сервис.

🎯 Цель:
Показать, как пользовательские или внешние действия инициируют последовательности вызовов в системе, и какие компоненты, модули или API участвуют в обработке.

📌 Требования:
- Отталкивайся **строго от кода проекта**, а не от документации
- Опиши **user/system flows**, где сервис является участником или инициатором
- Для каждого потока укажи:
  - 🔖 Название потока (например: «Сканирование QR и сохранение маппинга»)
  - 📋 Краткое описание — зачем этот поток нужен
  - 🧩 Участники (клиент, API Gateway, внешние сервисы, внутренние usecase-слои)
  - 🔄 Последовательность шагов (в виде списка, с реальными названиями функций, endpoints или методов)
  - 📤 Результат потока (например: запись в БД, публикация события, ответ клиенту)
  - ⚠️ Возможные ошибки, ветвления (если есть), ретраи, фолбэки

- Используй реальные названия:
  - HTTP/gRPC методов: `POST /api/v1/mapping`, `GetClientIntegrations()`
  - события и топики: `mapping.created.v1`
  - внутренние структуры: `clientRepository`, `mappingService`, `natsClient`

🛠 Формат:
- Markdown (`flows.md`)
- Один поток = один блок `##`
- Используй подзаголовки: `Описание`, `Участники`, `Шаги`, `Результат`, `Ошибки`

📂 Вывод:
Сгенерированный файл `flows.md` сохранить в корневой директории сервиса
