Сгенерируй Mermaid диаграмму, отображающую архитектуру на уровне Component View.

🎯 Цель:
Показать разбиение системы на микросервисы и компоненты, их взаимодействие, коммуникации и основные зависимости.

📌 Требования:
- Отталкивайся строго от фактической архитектуры проекта и его кода, а не от документации
- Отобрази:
    - Все основные микросервисы и их назначения
    - API Gateway, BFF, фронтенды (если есть)
    - Способы взаимодействия между сервисами: REST, gRPC, NATS, Kafka, Redis и другие каналы
    - Основные базы данных и хранилища: PostgreSQL, YugabyteDB, ClickHouse, MinIO и т. д.
    - Взаимосвязи: кто с кем общается и по каким протоколам

- Указывай:
    - Протокол взаимодействия (`REST`, `gRPC`, `pub/sub`, `DB`)
    - Примеры API методов, топиков, таблиц (если уместно)
    - Используй названия из реальных проектов, например: `qr-service`, `auth-admin-gateway`, `clickhouse`, `NATS`, `merchant-console-gateway-service`

🛠 Формат:
- Используй Mermaid `flowchart` с направлением `LR` (left-to-right) или `TB` (если сильно вертикально)
- Обозначай компоненты блоками: `[qr-service]`, `[(ClickHouse)]`, `[[NATS]]`, `((User))`
- Используй стрелки `-->`, `-.->` с подписями для протоколов и действий (например, `REST: GET /api/v1/qrs`, `NATS: qr.created.v1`)
- Для логики: используй `subgraph` по зонам (например, `subgraph Backend`, `subgraph Infrastructure`, `subgraph External Systems`)

📂 Вывод:
Диаграмму нужно сохранить в директории:
`documentations/diagrams/system/components.mmd`

🧩 Контекст:
Ты проектируешь backend-систему MoiQR, состоящую из множества микросервисов. Тебе нужно показать взаимодействие между основными компонентами: gateway, сервисами, брокерами, БД и внешними системами (например, 1С или сторонними API).
