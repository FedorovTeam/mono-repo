Сгенерируй Mermaid диаграмму, описывающую Code / Module View архитектуру сервиса.

🎯 Цель:
Показать структуру кода внутри сервиса: пакеты, слои, зависимости, интерфейсы и внедрение зависимостей (DI), согласно принципам Clean Architecture.

📌 Требования:
- Отталкивайся строго от исходного кода проекта, а не документации
- Отобрази слои: handler/controller → service/usecase → repository → storage/DB/gateway
- Учитывай использование интерфейсов, внедрение зависимостей, вызовы внешних клиентов
- Если сервис использует events, pub/sub, RPC или GraphQL, отрази, в каком слое это используется
- Покажи зависимости между пакетами и модулями Go, если структура monorepo — отрази конкретный подкаталог
- Названия сущностей должны соответствовать названиям файлов и структур (например, `saleHandler`, `mappingService`, `mappingRepository`)
- Если используются паттерны (например, фабрики, middleware, adapters, ports), тоже включи

🛠 Формат:
- Используй Mermaid `flowchart` с направлением `TB` (top-to-bottom)
- Используй блоки (`[Module]`) и стрелки (`-->`) для отображения зависимости
- Упрощай названия, чтобы диаграмма была читаемой, но не теряла смысл

📂 Вывод:
Диаграмму нужно сохранить в папке сервиса с названием code в формате MD внутри которого хранится Mermaid


🧩 Контекст:
Сервис: <название сервиса>
