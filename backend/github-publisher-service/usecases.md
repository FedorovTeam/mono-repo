# Use cases

## Публикация конвертированного документа
- **Актор:** workflow после шага конвертации DOCX → Markdown.
- **Шаги:**
  1. Получить готовый Markdown и ключ в MinIO.
  2. Вызвать `PublishMarkdown` с веткой `feature/doc-{id}` и путём `/knowledge/{id}.md`.
  3. Получить SHA коммита и номер PR.

## Перепубликация в новую ветку
- **Актор:** оператор поддержки.
- **Шаги:**
  1. Заполнить новый путь/ветку в запросе `PublishMarkdown`.
  2. Установить `create_pr=true`, указать `pr_title` и `pr_body` с причинами перепубликации.
  3. Проверить ссылку на PR из ответа.

## Обновление без PR
- **Актор:** фоновые задачи синхронизации.
- **Шаги:**
  1. Отправить `PublishMarkdown` без `create_pr` для прямого коммита в `main`.
  2. Использовать `author_name`/`author_email` для маркировки техпроцессов.
